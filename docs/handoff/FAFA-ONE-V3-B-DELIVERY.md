## 本次完成

- Owner 的注册时间窗口策略在自助注册模式下可用。窗口内新建并验证账户才符合资格，现有策略提供 1–3 天体验；到期从用户创建时间计算，补处理不延长，已存在永久或更长授权不缩短。节点仍须单独拥有或获源授权，第三方源须有再分发依据。
- Owner 可管理全站服务开始/结束时间。普通用户在窗口外不能下载新旧订阅、操作节点、连接 SSH、执行 AI 或使用地点业务；账户、登录和后台管理入口保留，方便用户查看状态和管理员恢复。SSH 输入及看门狗、AI 开始和运行看门狗持续复查。已下载到客户端的节点配置无法由面板远程收回，节点服务端凭据的撤销仍由节点运营方负责。
- Admin/Owner 可统一管理 Member 的节点、服务器、AI 能力、订阅开关、节点数和 AI 次数/并发额度。流量政策仍标注未计量，不虚称流量限制已执行。
- Owner 可选择本人配置的 API 账户开放管理员 AI 服务，个人用户的提示和输出仍按任务所有者隔离；不向使用者暴露服务 API Key。服务次数和并发同时受全站每人上限及个人配额约束。滚动 24 小时计数，0 次为暂停，失败/取消任务也计入次数；不代表供应商货币预算。
- 保留个人 OpenAI API 账户；个人 Codex 授权明确暂未开放，不接收 ChatGPT Cookie、登录令牌或 CLI 凭据文件。官方接入参考：https://learn.chatgpt.com/docs/app-server 。未配置真实凭据时不假报 AI 可用或发起付费调用。

## 测试与发布证据

新增 `tests/service-policy.integration.test.ts` 覆盖时段左右边界、权限、旧令牌到期、资源所有权、个人配额、跨用户隔离及停用服务后的 Worker 阻断；浏览器增加后台服务策略及用户 AI 配额交互。

`infra/scripts/test-v3-ec2.py` 仅连接标记的隔离 PostgreSQL，并将 Owner 初始化套件与工作台夹具放在不同测试库。`infra/scripts/test-v3-browser-ec2.py` 复用既有 Playwright 容器与合成邮件传输。测试日志记录实际运行 SHA，合成邮件不作为生产收件证据。

`infra/deploy/v3_ec2_release.py` 分阶段执行备份实际恢复、固定 SHA 构建、恢复库最小权限启动预检及 systemd/Compose 发布。生产迁移清单及文件必须与当前 Release 相同，不运行生产 migrate/seed/grant。Release 通过 Git archive 产生，未跟踪文件不进入镜像；部署保持既有环境文件、密钥、Owner、业务数据和持久卷。

关键发布检查失败时原子恢复上一 Release，并重启原 systemd 服务，不还原数据库覆盖新增数据。此前版本不理解新增全站时段策略：正式启用新策略后的后续人工回滚必须评估其授权语义，不能只凭旧镜像健康就宣称仍执行新策略。

最终状态以 `/opt/fafa-one/reports/b-v3-*` 中实际候选 SHA 对应的备份、构建、预检、部署和线上验收 JSON 为准。本文件不预先宣称已经上线或实际收件验收通过。
