# 应用、数据库与任务回滚

每次变更前保存验证过的数据库备份、镜像 digest、配置版本和外部任务状态。仅操作 FAFA 独立 Compose 项目，不执行全局容器清理或更改现有 Caddy 站点。

1. 停止创建新任务；请求并核实外部 worker 的活动任务终止或完成。先暂停本项目 api/frontend 写入。
2. 若仅前端/API 代码回退且 schema 完全兼容，在独立 override 文件中引用前一版经测试镜像 digest，启动该项目并健康检查。不要删除持久卷。
3. schema 不兼容时，恢复备份到**新数据库**，新配置指向它，使用匹配旧 schema 的应用镜像。当前迁移故意禁止破坏性 downgrade，不能假定 Alembic downgrade 会安全撤销数据。
4. 撤销恢复库内的历史 session、auth_tokens、oauth_flows；按部署手册验证权限、最后管理员保护、用户/角色/审计数量和新登录。保持旧数据库直到完成对账。
5. 若回退到 v0.3，要把用户数据备份恢复成 v0.3 格式并重新评估旧版安全缺陷，不能让 v0.3 直接读取 v1 schema。优先前向修复，不建议生产回到旧鉴权实现。

节点配置版本回滚会重新验证并暂存历史 JSON，生成新的配置版本。它不是自动服务重启；确认运行中服务加载情况后才可宣称数据面回滚完成。UI/审计会保留操作结果。

Codex 代码回滚只允许管理员对真实 succeeded、持有 remote job ID 的任务请求 worker `/rollback`。只在 worker 明确返回 rolled_back 后记录成功。worker 必须在独立工作区执行，禁止把未审查 diff 写到生产服务器。外部网络异常时保持回滚未确认，先核对远端 Git 状态，避免重复操作。没有 worker 就没有真实代码回滚。
